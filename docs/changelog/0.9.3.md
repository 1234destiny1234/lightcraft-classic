# 0.9.3

The changes since [0.9.2](0.9.2.md). After each item, the matching upstream pull request: `(↑ #n)` means the
maintainer of this fork opened it upstream, `(⇠ #n)` means it was ported from an upstream PR, and `(no PR)`
means there is none (the change is in the fork's own Classic layout or a fork issue with no upstream counterpart).

The catalog format is unchanged from 0.9.2 (version 12).

## Highlights

- **Network drives and shares keep working:** upstream now follows the originals a Lightroom catalog lists only on
  this computer or on the share the catalog itself is on, and leaves the rest out of the import. The fork keeps
  following originals on any network drive or share (mapped drives, `\server\share` paths, SMB/NFS mounts),
  wherever the catalog is; only device paths and URLs are refused. Fork #273. (no PR: fork difference)
- **Latest upstream merged:** 13 upstream changes, listed below. Fork #273.

## From upstream

- **Only photo files reach the system opener:** a catalog record naming a program (`.exe`, `.lnk`, `.app`, …) is
  never imported or handed to another application. (⇠ #2199, for upstream issue #2135)
- **XMP sidecars are written only beside an existing original,** so a missing original no longer gets a stray
  sidecar. (⇠ #2175)
- **Float images with non-finite samples** are clipped safely instead of showing garbage. (⇠ #2071)
- **Shifting a capture time without seconds keeps its time zone.** (⇠ #2146)
- **Search words with an unknown field prefix** are searched as plain text. (⇠ #2099)
- **Assisted Culling bursts that cross midnight at month end** stay one burst. (⇠ #2095)
- **Offline reverse geocoding** finds cities at longitude exactly 180. (⇠ #2061)

## Upstream pull requests

All the upstream items are **merged** upstream (#2071, #2146, #2099, #2095, #2061, #2175, #2199). The
network-share behaviour of #2175 is deliberately not taken; see the README's comparison table.
