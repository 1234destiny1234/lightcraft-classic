# 26.43.6

The changes since [26.43.5](26.43.5.md). After each item, the matching upstream pull request: `(↑ #n)` means the
maintainer of this fork opened it upstream, `(⇠ #n)` means it was ported or merged from an upstream PR, and
`(no PR)` means there is none (the change is in the fork's own layout, the fork's Android app, or a fork issue with no
upstream counterpart).

The sixth release of week 43 of 2026. The catalog format is unchanged (version 13).

## Develop

- **High quality adjustment previews:** an optional setting (Settings ▸ Performance) keeps slider adjustments at the
  settled render's quality, size and display fit, including zoomed views, Before/After and HDR. When an edit is too
  slow for it, the moving slider falls back to the faster previews and full quality returns as soon as the slider
  holds still. The faster adaptive previews stay the default. Thanks @Kaan88. Fork #426, #458. (no PR)
- **HDR while dragging:** adjustment previews stay on the HDR display path while a slider moves, and stale
  asynchronous results are dropped. Thanks @Kaan88. Fork #423. (no PR)
- **Preview for SDR Display:** with HDR editing on, a box under Visualize HDR shows an HDR edit's SDR rendition on an
  HDR display (the same switch as View ▸ HDR Preview); the SDR Rendition sliders are greyed out while the screen
  shows HDR. Fork #459. (no PR)
- **Plugins:** a filter can be measured on the cropped photo (`analyzeArea`), a Source filter can turn off a raw's
  base tone (`baseTone`), and choice parameters can group their options. Thanks @nwh212. Fork #444, #452, #454.
  (no PR)

## Library

- **Grid stays put:** the selected photo holds still through side-panel resizes and filter changes, and the top
  photo keeps its place when panels resize. Fork #447, #460. (no PR)

## From upstream

Upstream's integration batch 43 (#2744) and three upstream fixes, merged in fork #457:

- **Multi-select metadata editing** in the Metadata panel. (⇠ #2622)
- **Enable Filters** on Cmd+L / Ctrl+L; Find Similar turns filtering on, and a put-aside filter follows renamed
  keywords, people and folders. (⇠ #2709)
- **All-masks overlay** outlines every visible mask. (⇠ #2210)
- **Auto straighten** turns at most 10°, needs at least 3 lines and says when it finds nothing. (⇠ #2688)
- **PSD / PSB metadata** is read from the file. (⇠ #2546)
- **Highlights / Shadows** about 2× faster on the CPU, with identical results. (⇠ #2694)
- **Library:** Synchronize Folder takes removed photos out of their stacks (⇠ #2543); Find Similar with no matches
  shows an empty view (⇠ #2109); smart album ≥ / ≤ match equal f-number and focal length (⇠ #2728); Find Missing
  Photos matches Windows paths by name on macOS and Linux (⇠ #2618); the library lock never writes through a link
  (⇠ #2596).
- **Interface:** the macOS menu gives its keys up to text fields and the shortcut recorder (⇠ #2621); Tab leaves the
  name field of New Album and similar prompts (⇠ #2727).
- **XMP:** namespaces are owned by URI, so foreign prefix collisions are preserved. (⇠ #2526)
- **Automation:** colour-range samples are capped (⇠ #2670), `view.maskOverlayColor` refuses signed hex digits
  (⇠ #2626), the command list is sorted by id (⇠ #2665), and the command sweep no longer starts a GeoNames download
  (⇠ #2702).
- **Hardening and tests:** dev-tool path validation (⇠ #2494), a documented thread-teardown buffer (⇠ #2700), corpus
  tests for Nikon Z 8 / Z 6II and Hasselblad TIFF (⇠ #2620), and test fixes (⇠ #2612, #2630). The README shows the
  app icon (⇠ #2548).

## Release builds and CI

- **Play Store build:** `cargo xtask android package --aab` builds the Play variant without All files access (Play
  refused the bundle); the GitHub APKs keep it (`--store github|play`). The camera roll handles Android 14's
  selected-photos access. `--version-code` overrides the Android version code. Fork #442, #445, #446. (no PR)
- Windows clippy fix in an engine test. Fork #461. (no PR)
