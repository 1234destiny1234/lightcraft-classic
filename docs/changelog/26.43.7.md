# 26.43.7

The changes since [26.43.6](26.43.6.md). After each item, the matching upstream pull request: `(↑ #n)` means the
maintainer of this fork opened it upstream, `(⇠ #n)` means it was ported or merged from an upstream PR, and
`(no PR)` means there is none (the change is in the fork's own layout, the fork's own tools, or a fork issue with no
upstream counterpart).

The seventh release of week 43 of 2026. The catalog format is unchanged (version 13).

## Interface

- **Modern – Simple layout** (Settings ▸ General ▸ Layout), replacing the touch layout: a photo-first Develop with a
  dock of adjustment groups and tools (bottom or side), cards of pill sliders, a ☰ menu bar with Shortcuts, and a
  floating histogram with two sizes. Every develop setting is reachable from it, the chrome fades away while an
  adjustment is dragged, the Library gets an Info card and a search pill, Import and Export open as full-window
  screens, dialogs are rounded cards (bottom sheets on a phone). Classic is now called **Classic – Advanced**.
  Fork #464, #483. (no PR)
- **Pill sliders** (Settings ▸ Interface ▸ Sliders): the name and value inside one bar you drag anywhere. Fork #464.
  (no PR)

## Develop

- **Camera calibration matched to Lightroom** (`calibrate-lightroom` in the command-line tool): contributors fit a
  camera's colour model and one look per Lightroom profile (Adobe Standard, Color, Vivid, Landscape, Portrait,
  Monochrome…) to Lightroom's exports of their own raws (`preset`, `fit`), and send the resulting file of aggregate
  numbers; developers add it with `add`, and `list` shows the built-in ones. A calibrated camera's looks appear in the
  Camera Profile menu under our names (e.g. *Eboda Colour*), and photos imported from Lightroom sidecars and
  catalogues pick the look matching their Lightroom profile. The guide covers running the tool on Windows, macOS and
  Linux. No camera is calibrated yet. Fork #485. (no PR)

## Library

- **Import metadata presets:** apply metadata presets directly in the Import Photos dialog with an always-visible
  preset selector, preselecting the default from Settings, and create new metadata presets inline or import preset
  files; the picker is on the new Import screen too. Thanks @deunderscorepaul. Fork #467, #472. (no PR)

## Display

- **HDR adjustment previews, follow-up:** dragging a slider on an HDR edit redraws only the views of the photo being
  edited and no 8-bit previews under the HDR picture; zoomed in, parts the HDR picture can't cover show sharp; a crop
  or rotation never shows the old shape, and a preview that fails to render no longer leaves an outdated one on
  screen. Thanks @Kaan88. Fork #423 follow-up, #474, #482. (no PR)

## Performance

- **Faster HDR zoom and drags:** HDR previews are prepared for the display off the interface thread, zoomed views
  keep their last few HDR windows (a pan back or a zoom back in is sharp at once, a pan keeps the part already sharp),
  and no unseen 8-bit tiles are rendered under them; a 1:1 HDR drag's frames take ~2 ms of interface time instead of
  ~15 ms. The kept windows are freed from graphics memory as soon as they go, and Settings ▸ Display & Speed offers
  them only where the graphics card has room (at most a quarter of its memory; greyed out with the reason
  elsewhere). Thanks @Kaan88. Fork #475, #484. (no PR)

## Updater and security

- **Edit In uses the editors you set up:** over MCP, the control channel and in actions, `photo.editIn`,
  `photo.openAsLayers` and `editIn.savePreset` no longer take a program (`app`, `args`, `control`), the Edit In menu
  commands no longer take `app`, and `ui.set` can't change the editors in Settings ▸ External Editing; a saved Edit In
  preset or the editor in Settings opens instead. The command line (`run` without `--connect`) and the Edit In Presets
  dialog still choose one. On Windows, the system's default editor is started through Explorer rather than the command
  prompt (`cmd`). Thanks @clydecbrown. Fork #479, #480. (no PR)

  (no PR)
- **Connections:** an Immich server's buttons wrap instead of running off a narrow Settings window. (no PR)
