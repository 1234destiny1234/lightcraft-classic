# 26.43.5

The changes since [26.43.4](26.43.4.md). After each item, the matching upstream pull request: `(↑ #n)` means the
maintainer of this fork opened it upstream, `(⇠ #n)` means it was ported or merged from an upstream PR, and
`(no PR)` means there is none (the change is in the fork's own Classic layout, the fork's Android app, or a fork
issue with no upstream counterpart).

The fifth release of week 43 of 2026. The catalog format is unchanged (version 13). Raws from Sony bodies with DRO,
and Canon, Panasonic, Leica and Pentax raws now edited in Kelvin, may look slightly different after the update (see
From upstream).

## Highlights: the touch layout and the Android app

- **Touch layout:** a photo-first layout for tablets, foldables and phones, on by default on Android and available
  everywhere, the web app included, through Settings ▸ General ▸ Layout (Touch / Desktop; remembered, and the same row switches back).
  Develop shows the photo alone; a tap brings a slim top bar and a tool strip. The slider tools (Basic with white
  balance and tone, Colour with presence, Tone with the parametric curve, Detail, Optics, Effects with vignette and grain) adjust one
  setting at a time by dragging on the photo, with Done / Cancel; hold the photo to see the original; the full Edit
  panel opens beside or under the photo. Fork #439. (no PR)
- **Gestures and Back:** swipe scrolling with momentum, long-press multi-select, and Android Back (including
  predictive back) one step at a time: it closes the Export sheet, steps out of a Settings page, leaves adjust mode,
  then the module. The layout keeps clear of the camera cutout and the system bars, and the histogram can be pinned
  or float over the photo. Fork #439. (no PR)
- **Touch Settings and Export:** a touch Settings page with the Layout row, and an Export sheet that saves to
  Pictures or shares the exported photo to another app. Fork #439. (no PR)
- **Touch Library:** a slim Library bar; Import offers photos, a folder or the camera roll, and an empty library
  shows big Import Photos / Import Folder / Camera Roll buttons instead of desktop hints. Fork #439. (no PR)
- **Android folder import and camera roll:** File ▸ Import from Folder… works on Android. A folder on the device is
  read in place with "All files access"; without it the folder is copied and stays linked. On the first start the
  app offers to add the camera roll (DCIM/Camera, through the photo permission); the answer is remembered and
  Settings ▸ Folders offers it again. Fork #421, #439. (no PR)
- **Android fixes:** photos picked from the system picker import again (opened through MediaStore when the media
  provider refuses the document); the app no longer freezes on first start when sent to the background while it
  asks for All files access; a touch tap clicks. Fork #429, #436, #439. (no PR)

- **Privacy policy:** `PRIVACY.md` says what the app collects (nothing), every feature that goes online and how to
  avoid it, and what each Android permission is for. Fork #441. (no PR)

## Develop

- **Develop panel no longer jumps:** the Calibrated camera colour and Camera local tone mapping options stay shown
  while a photo is decoded again (an edit, crop mode), AI Denoise progress moved to the activity stack, and the
  masking status line keeps its space, so controls never move under the pointer. Fork #418. (no PR)
- **No one-pixel shifts while adjusting:** the photo no longer moves by a pixel while a slider is dragged, whatever
  the preview's resolution. Thanks @Kaan88. Fork #424, #434. (no PR)
- **Auto Sync white balance:** syncing a Temperature or Tint edit gives every selected raw the same Kelvin and tint,
  instead of a different value on raws whose white balance was still on the old relative scale. Fork #425, #430.
  (no PR)

## Library

- **Colour label shortcuts toggle:** **6–9** turn a colour label off when it is already assigned, and **Shift+6–9**
  toggle and advance, as in Lightroom Classic. Thanks @deunderscorepaul. Fork #412, #416. (no PR)
- **Keyword hierarchies typed with > and <:** the Add keyword box reads `animal > dog` and `dog < animal` as *dog*
  inside *animal* instead of one literal keyword. Fork #413, #428. (no PR)
- **Keyword List parents:** a selected photo with only a keyword below another shows a dash in the parent's tick
  box; clicking it adds the parent keyword. Fork #413, #435. (no PR)
- **Faster keyword tree:** the Keyword List is built from the keyword index and cached, so large keyword sets no
  longer slow the panel down. Fork #371, #437. (no PR)

## Interface

- **Slider text size:** Settings ▸ Interface ▸ Slider text offers Full Size, the regular text size for slider names
  and values (one row or two); Compact stays the default. Fork #415. (no PR)
- **File name in the filmstrip:** a source line above the filmstrip shows the source, the photo count, the
  selection and the active photo's file name, as in Lightroom Classic. Fork #419. (no PR)
- **Plug-in Filters:** clicking the section header opens the section. Thanks @nwh212. Fork #431. (no PR)
- **Identity plate colour:** the colour field takes only six hex digits. Thanks @clydecbrown. Fork #432, #433.
  (no PR)

## From upstream

- **Smoother camera tone on raws:** fitted camera tone curves are smoothed, and a DRO-lowered Sony curve follows
  Sony's curve between knots, ending posterized skin and satin. Sony raws shot with DRO may look slightly different.
  Fork #420. (⇠ #2188)
- **Kelvin white balance for more raws:** Canon CR2 / CR3, Panasonic / Leica RW2 and Pentax PEF bodies without
  colour matrices read their white balance in Kelvin from the presets stored in the file. Fork #422. (⇠ #2527)
- **Short ERF / MEF raws refused:** an Epson ERF or Mamiya MEF whose raw strip runs past the end of the file is an
  error, not a huge allocation. Fork #414. (⇠ #2155)
- **Negative channels:** tests that negative channel values pass through every pipeline stage safely. Fork #417.
  (⇠ #2278)

## Fixes

- **Map right-click menu:** the menu keeps the place you right-clicked (or long-pressed), so Geotag Selected Photos
  Here, Save Location Here and Copy Coordinates work instead of the menu shrinking and doing nothing. Thanks
  @endthestart. Fork #323, #328. (no PR)
- **macOS updates from before the rename:** 0.9.x installs can update again. The disk image also holds the app under
  its earlier name, which their updater looks for, and the updater accepts an image built under an earlier name.
  Fork #411, #438. (no PR)

## Release builds and CI

- **Update manifest:** the release's `latest.json` step reads the release repository from `brand.toml` directly,
  so it no longer fails as it did for 26.43.4. Fork #410. (no PR)
